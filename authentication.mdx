Payment Gateway divides its API surface into two access tiers. Most read-oriented and payment-processing endpoints are **public** — you call them without any credential. A smaller set of administrative endpoints that can modify gateway behaviour, circuit breaker state, retry policies, and experiments are **protected** and require you to pass an internal API key via a request header.

<Info>
  There is no user-level authentication (no OAuth, no JWT). The internal API key is a shared secret intended for backend services and administrators, not end users.
</Info>

## Passing the Internal API Key

Include the key as a custom HTTP header named `X-Internal-Api-Key` on every request to a protected endpoint.

```bash
curl -X PATCH http://localhost:3000/gateways/razorpay \
  -H "Content-Type: application/json" \
  -H "X-Internal-Api-Key: your-api-key" \
  -d '{ "successRate": 0.90 }'
```

The header name is **case-insensitive** at the HTTP transport level, but use `X-Internal-Api-Key` (Title-Case) as shown above to match the convention used throughout this documentation.

<ParamField header="X-Internal-Api-Key" type="string" required>
  Your internal API key. Pass this header on every request to a protected endpoint.
</ParamField>

## Error Responses

When you call a protected endpoint with a missing or incorrect key, the API returns an HTTP `401 Unauthorized` response.

```json
{
  "statusCode": 401,
  "message": "Missing or invalid internal API key",
  "error": "Unauthorized"
}
```

There is no distinction between a missing key and a wrong key in the error response — both return the same `401`. Verify that you are reading the key from the correct environment variable and that no extra whitespace has been introduced.

## Default Development Key

<Warning>
  The default key shipped with the development environment is `dev-internal-key-change-in-prod`. This key is publicly known and **must be replaced** before you deploy to any non-local environment. Set the `INTERNAL_API_KEY` environment variable to a securely generated secret in staging and production.
</Warning>

To rotate the key, update the environment variable that the Payment Orchestrator and Experiment Service read at startup, then restart both services. All callers must update their stored key at the same time — there is no key versioning or grace period.

## Security Best Practices

- **Never expose the internal API key in client-side code**, browser applications, or mobile apps. It is a server-to-server credential only.
- **Treat the key like a password.** Store it in a secrets manager or environment variable, not in source control.
- **Restrict access at the network level.** Protected endpoints are intended for internal operational tooling. Consider placing them behind a private network boundary so they are unreachable from the public internet.
- **Rotate the key regularly.** If you suspect the key has been compromised, change it immediately and restart the affected services.

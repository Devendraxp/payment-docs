---
title: "GET /metrics/history/{gatewayName} — Historical Metrics"
sidebarTitle: "GET /metrics/history"
description: "Query persisted historical metric snapshots for a gateway from PostgreSQL, enabling trend analysis beyond the rolling in-memory windows."
---

The `/metrics/history/{gatewayName}` endpoint retrieves metric records that have been persisted to PostgreSQL by the metrics service's scheduled flush job. Unlike the hot-metrics endpoints — which serve data from a Redis-backed, in-memory sliding window — the history endpoint gives you access to longer-term metric snapshots that are written periodically and retained for trend analysis. No authentication is required.

## Endpoint

```
GET http://localhost:3001/metrics/history/{gatewayName}
```

## Path Parameters

<ParamField path="gatewayName" type="string" required>
  The gateway identifier whose history you want to retrieve. Examples: `cashfree`, `razorpay`, `payu`, `juspay`. The endpoint returns up to 240 of the most recent records, ordered by recording time descending.
</ParamField>

## Example Request

```bash
curl http://localhost:3001/metrics/history/cashfree
```

## Response Fields

The response is a JSON array of historical metric record objects. Each object represents one flushed metric snapshot for a specific gateway, payment method, and time window.

<ResponseField name="id" type="string (UUID)">
  Unique identifier for this metric record, automatically generated by PostgreSQL.
</ResponseField>

<ResponseField name="gatewayName" type="string">
  The name of the gateway this record belongs to (e.g., `"cashfree"`).
</ResponseField>

<ResponseField name="method" type="string">
  The payment method this record covers (e.g., `"UPI"`, `"CARD"`, `"NETBANKING"`, `"WALLET"`).
</ResponseField>

<ResponseField name="successRate" type="number">
  The success rate for this gateway and method during the recorded window, as a decimal between `0` and `1`.
</ResponseField>

<ResponseField name="p95LatencyMs" type="number">
  The 95th-percentile latency in milliseconds during the recorded window.
</ResponseField>

<ResponseField name="attemptCount" type="integer">
  Total number of payment attempts recorded during this snapshot window.
</ResponseField>

<ResponseField name="recordedAt" type="string (datetime)">
  ISO 8601 timestamp indicating when this metric snapshot was recorded (floored to the nearest minute by the flush job).
</ResponseField>

<Note>
  **Hot metrics vs. historical metrics serve different purposes.** Hot metrics (available via `/metrics/gateways`) are kept in Redis, computed from a rolling in-memory buffer, and reflect the last 1, 5, 15, or 60 minutes of activity — they are what the routing engine uses in real time. Historical metrics (this endpoint) are periodically flushed from that same buffer into PostgreSQL and are intended for trend analysis, dashboards, and post-incident review. Because the flush runs on a schedule, the most recent history record may lag behind the current hot metric values by up to one flush interval.
</Note>

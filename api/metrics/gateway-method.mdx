sidebarTitle: "Gateway Methods"

---

The metrics service exposes two scoped endpoints that let you drill into the performance of a single gateway. You can either fetch metrics for all payment methods on a gateway at once, or narrow your request to a specific method such as `UPI` or `CARD`. Both endpoints return the same rolling-window statistics as the all-gateways endpoint, just scoped to the resource you specify. No authentication is required.

## Endpoints

| Variant | URL |
|---|---|
| All methods for a gateway | `GET http://localhost:3001/metrics/gateways/{gatewayName}` |
| Single method for a gateway | `GET http://localhost:3001/metrics/gateways/{gatewayName}/{method}` |

## Path Parameters

<ParamField path="gatewayName" type="string" required>
  The gateway identifier, lowercase. Examples: `razorpay`, `cashfree`, `payu`, `juspay`.
</ParamField>

<ParamField path="method" type="string">
  The payment method to filter by. The value is case-insensitive — the service normalises it to uppercase internally. Supported values: `UPI`, `CARD`, `NETBANKING`, `WALLET`. Omit this parameter to retrieve metrics for all methods on the gateway.
</ParamField>

## Example Requests

**All methods for a gateway:**

```bash
curl http://localhost:3001/metrics/gateways/cashfree
```

**Single method for a gateway:**

```bash
curl http://localhost:3001/metrics/gateways/razorpay/UPI
```

## Response Fields

### All-methods response (`/metrics/gateways/{gatewayName}`)

<ResponseField name="gateway" type="string">
  The gateway name as provided in the path parameter.
</ResponseField>

<ResponseField name="methods" type="object">
  A map of payment method names to their metric objects. Each method object has the same structure as the `metrics` field described below.
</ResponseField>

### Single-method response (`/metrics/gateways/{gatewayName}/{method}`)

<ResponseField name="gateway" type="string">
  The gateway name as provided in the path parameter.
</ResponseField>

<ResponseField name="method" type="string">
  The uppercased payment method name (e.g., `"UPI"` even if you passed `"upi"`).
</ResponseField>

<ResponseField name="metrics" type="object">
  The hot metric data for this gateway and method combination. Each field name is suffixed with the window duration: `_1m`, `_5m`, `_15m`, or `_60m`.

  <Expandable title="metrics fields">
    <ResponseField name="success_rate_{window}" type="number">
      Rolling success rate over the window, as a decimal between `0` and `1`. Computed as `successCount / totalCount`; returns `0` when there are no attempts.
    </ResponseField>

    <ResponseField name="success_{window}" type="integer">
      Number of payment attempts that returned a `SUCCESS` status within the window.
    </ResponseField>

    <ResponseField name="fail_{window}" type="integer">
      Number of payment attempts that returned a `FAILED` status within the window.
    </ResponseField>

    <ResponseField name="timeout_{window}" type="integer">
      Number of payment attempts that returned a `TIMEOUT` status within the window.
    </ResponseField>

    <ResponseField name="total_{window}" type="integer">
      Total number of payment attempts within the window, including successes, failures, and timeouts.
    </ResponseField>

    <ResponseField name="p50_{window}" type="number">
      50th-percentile (median) latency in milliseconds over the window.
    </ResponseField>

    <ResponseField name="p95_{window}" type="number">
      95th-percentile latency in milliseconds over the window.
    </ResponseField>

    <ResponseField name="p99_{window}" type="number">
      99th-percentile latency in milliseconds over the window.
    </ResponseField>

    <ResponseField name="last_updated" type="string">
      ISO 8601 timestamp of the last time this metric entry was updated.
    </ResponseField>
  </Expandable>
</ResponseField>

<Tip>
  The routing engine's scoring algorithm reads these exact metrics in real time when it decides which gateway to try first. A higher `success_rate_5m` and a lower `p95_5m` both contribute to a higher routing score, meaning a gateway with consistently fast, successful responses will be preferred over one with degraded metrics — even if only briefly.
</Tip>

---
title: "GET /metrics/gateways — All Gateway Hot Metrics"
sidebarTitle: "GET /metrics/gateways"
description: "Retrieve the rolling 5-minute sliding window hot metrics for every registered gateway and payment method in a single response."
---

The `/metrics/gateways` endpoint returns real-time hot metrics for all gateways currently tracked by the metrics service. Metrics are computed from an in-memory sliding window of payment attempt events — sourced from Kafka — and cached in Redis. The response groups results by gateway name and then by payment method, giving you an instant snapshot of how every gateway is performing right now. No authentication is required to call this endpoint.

## Endpoint

```
GET http://localhost:3001/metrics/gateways
```

## Request

This endpoint accepts no query parameters or request body.

## Example Request

```bash
curl http://localhost:3001/metrics/gateways
```

## Response Fields

The top-level response contains a single `gateways` key whose value is an object keyed by gateway name. Each gateway value is itself an object keyed by payment method (e.g., `UPI`, `CARD`). Each method entry contains the following fields:

<ResponseField name="gateways" type="object" required>
  A map of gateway names to their per-method metric objects.

  <Expandable title="gateways[gatewayName]">
    <ResponseField name="[method]" type="object">
      Metrics object for a specific payment method within this gateway.

      <Expandable title="method metrics">
        <ResponseField name="success_rate_5m" type="number">
          Rolling success rate over the last 5 minutes, expressed as a value between `0` and `1` (e.g., `0.9732` means 97.32% success rate).
        </ResponseField>

        <ResponseField name="p95_5m" type="number">
          95th-percentile latency in milliseconds over the last 5-minute window. Useful for assessing tail latency; lower values indicate a more responsive gateway.
        </ResponseField>

        <ResponseField name="attempts_5m" type="integer">
          Total number of payment attempts recorded in the last 5-minute window, including successes, failures, and timeouts.
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

<Note>
  Hot metrics are **eventually consistent**. Because events flow through Kafka before being processed and written to Redis, there may be a brief delay of a few seconds between when a payment is processed and when its outcome is reflected in these metrics. Do not rely on this endpoint for strict real-time consistency guarantees.
</Note>

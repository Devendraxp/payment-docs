---
title: "List All Configured Payment Gateways — GET /gateways"
sidebarTitle: "List Gateways"
description: "Retrieve all configured payment gateways, including their success rates, latency baselines, supported methods, and affinity configuration."
---

The `GET /gateways` endpoint returns every payment gateway registered in the orchestrator, along with the full configuration for each one. You can use this endpoint to inspect baseline success rates, latency profiles, and per-method or per-bank affinity weights before routing decisions are made. No authentication is required.

## Endpoint

```
GET http://localhost:3000/gateways
```

## Example Request

```bash
curl http://localhost:3000/gateways
```

## Response

The endpoint returns an array of gateway objects. Each element in the array has the following fields.

<ResponseField name="id" type="string" required>
  Unique UUID for the gateway record.
</ResponseField>

<ResponseField name="name" type="string" required>
  Internal machine-readable identifier used in routing and circuit-breaker keys. Known values include `razorpay`, `cashfree`, `payu`, `juspay`, and `hdfc_gateway`.
</ResponseField>

<ResponseField name="displayName" type="string" required>
  Human-readable label for the gateway, suitable for dashboards and logs (e.g., `"Razorpay"`).
</ResponseField>

<ResponseField name="successRate" type="number" required>
  Baseline success rate expressed as a decimal between `0` and `1`. For example, `0.87` means 87 % of transactions are expected to succeed under normal conditions.
</ResponseField>

<ResponseField name="baseLatencyMs" type="integer" required>
  Baseline p50 response latency in milliseconds under normal load.
</ResponseField>

<ResponseField name="supportedMethods" type="string[]" required>
  List of payment methods accepted by this gateway. Possible values are `UPI`, `CARD`, `NETBANKING`, and `WALLET`. The orchestrator will not route a payment to a gateway if the requested method is absent from this array.
</ResponseField>

<ResponseField name="methodAffinity" type="object" required>
  Scoring multipliers keyed by payment method. A value greater than `1.0` boosts the gateway's score for that method; a value less than `1.0` penalises it. Example: `{ "UPI": 1.2, "CARD": 0.9 }`.
</ResponseField>

<ResponseField name="bankAffinity" type="object" required>
  Scoring multipliers keyed by bank name (uppercased). Used to favour or deprioritise a gateway for customers of a specific bank. Example: `{ "HDFC": 1.15, "ICICI": 1.05 }`.
</ResponseField>

<ResponseField name="amountTiers" type="object" required>
  Scoring multipliers for transaction amount ranges. Typical keys are `small`, `medium`, and `large`, with numeric multipliers. Example: `{ "small": 1.1, "medium": 1.0, "large": 0.95 }`.
</ResponseField>

<ResponseField name="timePenalties" type="object" required>
  Hour-of-day penalty map (24-hour clock, UTC). Keys are hour strings and values are penalty offsets applied to the gateway's time score during that hour. Example: `{ "2": 0.8, "3": 0.75 }` adjusts the gateway's score between 02:00 and 04:00 UTC.
</ResponseField>

<ResponseField name="enabled" type="boolean" required>
  When `false`, the gateway is excluded from all routing decisions regardless of its score.
</ResponseField>

<ResponseField name="createdAt" type="string" required>
  ISO 8601 timestamp of when the gateway record was created.
</ResponseField>

<ResponseField name="updatedAt" type="string" required>
  ISO 8601 timestamp of when the gateway record was last updated.
</ResponseField>

---
title: "GET /bandit/order/{segment} — Sample Gateway Order"
sidebarTitle: "GET /bandit/order"
description: "Sample a Thompson-optimal gateway ordering for a set of gateways in a given segment by drawing from each gateway's Beta distribution."
---

The `/bandit/order/{segment}` endpoint draws a fresh Thompson Sampling score from each gateway's Beta distribution and returns the gateways sorted by their sampled score, highest first. This is the ordering the payment router uses when the bandit algorithm is active: gateways that have demonstrated higher success rates over time tend to appear earlier in the list, but stochastic sampling ensures occasional reordering so the system continues to explore and adapt. No authentication is required.

## Endpoint

```
GET http://localhost:3002/bandit/order/{segment}
```

## Path Parameters

<ParamField path="segment" type="string" required>
  The payment segment to sample gateway ordering for. Typically the uppercased payment method — for example, `UPI`, `CARD`, `NETBANKING`, or `WALLET`. The bandit reads the Beta distribution parameters for each gateway within the matching segment.
</ParamField>

## Query Parameters

<ParamField query="gateways" type="string" required>
  A comma-separated list of gateway names you want ranked. The bandit samples from the Beta distribution state of each gateway in the list and returns them sorted by descending sampled score. Gateways that have no prior state default to `Beta(1, 1)` — a uniform distribution — which means they are treated as completely unknown and explored at a neutral prior. Example: `cashfree,razorpay,payu,juspay`.
</ParamField>

## Example Request

```bash
curl "http://localhost:3002/bandit/order/UPI?gateways=cashfree,razorpay,payu,juspay"
```

## Response

The response is a JSON array of gateway name strings, ordered from most-preferred to least-preferred based on the Thompson Sampling draw. The payment orchestrator uses this array as its priority list — it attempts the first gateway, falls back to the second on failure, and so on.

## Example Response

```json
["razorpay", "cashfree", "payu", "juspay"]
```

<Note>
  The ordering returned by this endpoint is **stochastic**. Two identical requests made milliseconds apart may return different orderings, because each call independently samples from the underlying Beta distributions. This is by design: Thompson Sampling's power comes from this controlled randomness — it concentrates traffic on the best-performing gateways while retaining the ability to discover improvements in gateways it has less data on. Over many calls, gateways with higher `alpha` relative to `beta` will statistically appear first more often, but no gateway is ever permanently excluded from consideration.
</Note>

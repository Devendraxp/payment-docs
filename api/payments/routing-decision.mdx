---
title: "GET /payments/{paymentId}/routing-decision — Inspect Routing"
sidebarTitle: "GET /routing-decision"
description: "Retrieve the stored routing decision for a payment, including the ranked gateway list, per-gateway scores, the selected gateway, and the routing reason."
---

The `GET /payments/{paymentId}/routing-decision` endpoint returns the gateway selection decision that was recorded at the moment the payment was processed. The routing engine evaluates every available gateway against a set of scoring factors — historical success rate, latency, payment method compatibility, bank affinity, amount range, and time-of-day patterns — then ranks them from most to least preferred. The orchestrator works down that ranked list until a gateway succeeds or all options are exhausted. This endpoint lets you audit exactly how and why a particular gateway was chosen.

<Note>
  The routing decision is a **snapshot** captured at payment creation time. Gateway scores are recalculated continuously as new payment data arrives, so the scores stored here may differ from current live scores. Use this endpoint for historical auditing, not for predicting future routing behaviour.
</Note>

---

## Endpoint

```
GET http://localhost:3000/payments/{paymentId}/routing-decision
```

---

## Path Parameters

<ParamField path="paymentId" type="string" required>
  The UUID of the payment whose routing decision you want to inspect.
</ParamField>

---

## Example Request

```bash
curl http://localhost:3000/payments/b3e2a1d4-7f6e-4c5b-9a8d-123456789abc/routing-decision
```

---

## Response Fields

<ResponseField name="id" type="string">
  UUID uniquely identifying this routing decision record.
</ResponseField>

<ResponseField name="paymentId" type="string">
  The UUID of the payment this routing decision belongs to.
</ResponseField>

<ResponseField name="rankedGateways" type="array of strings">
  The ordered list of gateway names as ranked by the routing engine at payment time, from most preferred (index `0`) to least preferred. The orchestrator tries gateways in this order.
</ResponseField>

<ResponseField name="selectedGateway" type="string | null">
  The name of the gateway that was actually selected and used for the first attempt. `null` if no gateway was available.
</ResponseField>

<ResponseField name="scores" type="object">
  A map of gateway name to score details. Each key is a gateway name (for example, `"RAZORPAY"`), and the value is an object containing the composite `score` and the individual `factors` that produced it.

  <Expandable title="Score object (per gateway)">
    <ResponseField name="score" type="number">
      The composite score assigned to this gateway for this payment, as a decimal between `0` and `1`. Higher scores indicate a stronger preference.
    </ResponseField>

    <ResponseField name="factors" type="object">
      The individual factor scores that were combined to produce the composite score. Factor names and values vary by routing configuration.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="reason" type="string | null">
  A human-readable explanation of the routing outcome — for example, why a particular gateway was selected or why routing fell through to a lower-ranked option.
</ResponseField>

<ResponseField name="createdAt" type="datetime">
  ISO 8601 timestamp of when this routing decision was recorded.
</ResponseField>

## Error Responses

| HTTP Status | Cause                                                              |
| ----------- | ------------------------------------------------------------------ |
| `400`       | The `paymentId` path parameter is not a valid UUID format.         |
| `404`       | No payment or routing decision exists for the given `paymentId`.   |
